## M2 已实现功能

| 模块 | 实际可用能力 | 数据边界 |
| --- | --- | --- |
| A. GMV 监控 | 总览、完整周趋势、相邻可比周期、原历史基线、异常事件及作用维度、贡献核对 | GMV 沿用购买订单商品金额；不等于实际净 GMV；未保存去年同期结果时明确不提供同比 |
| B. SKU 诊断 | 全部商品分页/搜索、金额/销量/均价排序、负向贡献、详情、数量效应/价格效应及原始精确证据 | Olist product_id 不自动等同于规格 SKU；新增/消失商品沿用组合效应口径 |
| C. 营销与流量 | 模拟活动状态、两期投放花费/点击/归因比较、自然和付费访问、趋势、下降信号及反证问题 | 真实独立广告仍缺点击/曝光/收入；不与 Olist JOIN。流量变化是描述性信号，不冒充新增正式告警规则 |
| D. 转化 | 曝光→点击→访问→详情→加购→结账→下单；各阶段分子、分母和转化率 | 独立模拟嵌套 cohort；零分母不适用；支付缺失，不把订单数写成支付数 |
| E. 库存与履约 | 库存快照/销售趋势、负库存标记、覆盖天数和低库存风险；模拟准时发货、配送延迟和关联订单评价 | 覆盖天数为快照库存/近七日日均销量；不是完整库存流水对账或缺货损失证明；真实 Olist 缺承诺发货截止时间时不生成准时发货率 |
| F. 调查 | 读取同版本证据包，输出事实、可能原因、反证、缺失数据、待验证假设、建议行动；支持追问记录 | 默认可选规则诊断，明确“非大模型”；真实模型入口保留但当前未接通 |
| G. 人工闭环 | 创建调查→人工审核→行动→执行凭证→后续版本复核→人工关闭；保留历史、版本和证据哈希 | 真实数据缺后续版本时保持未验证；模拟复核保存 `simulated_observation`，不能关闭真实任务 |

事件列表显示全店、商品、品类、卖家范围，不能把同指标的不同范围事件误认为重复。商品事件默认进入该商品证据。

## 模拟数据如何隔离

- 独立 schema：`olist_v21_sim`，与真实 `olist_v21` 分开。9 张表开启 RLS，普通应用身份不能直接调用写入 RPC。
- 独立私有文件桶：`olist-v21-simulated`。真实文件仍在 `olist-v21-private`；两者均非公开桶。
- 场景来源固定 `synthetic://gmv-drop-lab-v1`，manifest 强制 `is_synthetic:true`，商品/活动 ID 使用 `SIM-` 前缀。真实导入入口拒绝该标记，模拟入口拒绝真实标记。
- 上传的是明确标识的 `scenario.csv`：日×商品粒度。初始 140 行，后续完整快照 154 行，覆盖两个模拟商品；每个模拟订单对应一个商品件数。仅为演练，不是原 Olist 数据补全。
- 场景内订单和金额转换成原统一结构，复用原 `scripts/operations.cjs`、operations-2.0.0、monitoring-2.0.1 的 SQL/JavaScript 复核。默认阈值不变。服务端复用既有 `engine-process.cjs` 在子进程运行模拟计算，该原文件未修改。
- 流量、广告、转化、库存和履约演示字段来自同一模拟文件；不是把 Google、Mendeley 和 Olist 强行拼接。
- 所有页面、证据、调查报告、效果验证和导出带工作区/模拟标识。切换工作区立即清空旧视图，防止新标签下短暂显示旧数据。
- 最终数据库检查：真实 schema 中模拟版本为 0，模拟 schema 中非模拟版本为 0，活跃模拟任务为 0，事务回滚测试残留为 0。见 `evidence/m2-isolation-final.json`。

4. 一次 PowerShell 启动出现 `Internal CLR error (0x80131506)` 和退出 `-1073741819`。另有两次浏览器运行无输出退出，未取得原生崩溃位置；不能据此断言与此前 core.validate 崩溃同根因。
5. 中断留下的模拟任务 `385772d1-2857-4f42-a600-16f184998de6` 正确保留数据集锁，重复提交被拒。取消请求后等租约到期，通过原恢复 RPC 转为 canceled，没有强行解锁或发布候选。见 `evidence/m2-interrupted-recovery.json`。失败尝试记录未删除。
6. 场景服务复用原计算子进程机制隔离计算失败。随后 36 项回归与最终浏览器全链路通过。**这不是 Windows 根因修复，也不证明长期稳定。**
