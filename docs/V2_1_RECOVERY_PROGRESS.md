### 选择与证据结论

优先核查评价门禁，因为旧记录明确有 `rating / order_reviews.csv / row=83485 / review_score`。实际源码 `core.js validate()` 使用 PapaParse `header:false, delimiter:',', skipEmptyLines:true`，以 `j+2` 生成报告序号。因此该序号指**跳过空行后的逻辑 CSV 记录位置（含表头）**，一般情况下不能直接等同物理行；本次 Python 检查显示目标及相邻记录的物理结束行恰好与序号一致。

旧错误没有记录当时的字段实际值、字符编码或记录键；不能证明当时校验器看到的内容就是后来读取的合法 `4`。本轮新增只读诊断，在同一次真实 `Core.validate()` 调用所用的 PapaParse 边界记录 83,484 / 83,485 / 83,486 号记录的评分、Unicode 码及记录/主键哈希。它只代理 parser 返回结果，不改变解析配置、结果或校验逻辑。

实际观察：三个评分分别为 `5 / 4 / 1`，目标值为 ASCII `4`，码点 52；Python `csv.reader` 独立定位结果一致。未修改 `core.js` 或任何原始/标准 CSV。
