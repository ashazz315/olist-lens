# v2.0 首轮验收记录

日期：2026-11-14（Asia/Shanghai）。交付版本：`2.0.0-preview.1`；经营指标契约：`operations-2.0.0`；原 CSV 结构、履约计算和指标版本继续为 `1.0.0`。

## 已实现并验证

1. 设计先于实现：现有系统审计、数据可用性、指标字典、模块方案、测试矩阵、任务优先级均在 `docs/V2_DESIGN.md`。
2. 两个完整相邻等长整周周期比较；购买订单商品金额、订单、件数、平均订单商品金额、履约分子/分母；与旧 delivered 金额分别命名。
3. 商品并集贡献、件数/平均单价对称分解、精确有理数证据；新增/消失商品单列构成贡献，不虚构缺期价格。商品、品类、卖家、地区变化分别与总体对账。
4. SQL / 独立 JS 逐组核对；旧质量失败、缺明细、缺完整性或复算冲突阻断；低样本、缺商品 ID、历史不足和零基期抑制告警。
5. 完整快照导入自动执行 v2；预览确认后保存。运行、指标快照、文件/代码哈希、证据及本机候选告警可导出，重复导入不累加。
6. 同批历史变化中位数/MAD 与绝对/相对门槛组合；配置可保存到 manifest。告警需人工确认或驳回，行动单有审核门禁。
7. 确定性证据问答、缺数据明确“证据不足”、版本绑定、证据白名单；问答、人工审核与行动单记录本机持久化。没有实际大模型调用。

## 单元测试

命令：`node --test tests/core.test.cjs tests/operations.test.cjs`。

结果：**22/22 通过**，其中原版 7 项原样保留、新增 15 项。新增测试中的所有订单均为明确标注的合成样本，不代表真实 Olist 业务结果。

覆盖：多商品/多评价防放大、相同重复行去重、重复运行身份稳定、冲突键、购买订单缺商品、完整期间、时区与提取水位、非法配置、低样本、缺维度、历史覆盖、零分母/零差额、新增/消失商品、跨品类映射、历史 MAD、未来窗口不泄漏、SQL 篡改被独立复算发现、证据不足和未审核行动单拒绝。

精确分解的有理数恒等式另在 432 个组合中检查（12×12 种件数组合，3 组金额，含分数均价、零价格与大金额）；它们属于同一单元测试，不重复计为 432 项独立业务验证。

## 未执行或未交付的范围

- 没有提供真实全量规范化 CSV，因此没有重跑 `verify_case.py` 的真实数据 Python Decimal / SQLite 检查，也未执行旧浏览器脚本中的 99,441 单真实数据重新导入分支。现有公开报告中的旧验证记录属于历史，不冒充本次结果。
- 未用真实业务数据验证误报率、季节性或运营收益；阈值是可配置起点。
- 未做 80 MB / 单表 400,000 行的性能基准测试；旧限制保留但不等于新增模块已完成极限规模测试。
- 完整性依赖批次提供者的水位和证据声明，交易文件本身不能证明没有漏单。需要独立采集服务及源系统对账来加强保证。
- 首轮只支持固定整周窗口，不支持不同天数自然月、跨来源/跨币种比较、退款净 GMV 或流量漏斗。
- 没有后台采集、定时调度、外部通知、生产身份认证或真实模型深度集成。人工审核身份仅由本机用户自报。
- 质量检查失败的导入保留检查明细并阻止发布，不创建新的指标快照；本轮运行历史随可保存的完整快照管理，没有服务端全量任务日志。

结论：可审查、可本机运行的第一轮开发预览；不是已发布的生产 v2，也不代表全链路已经打通。
