# 业务指标缺口矩阵

审计日：2026-11-14。范围：本地官方 Olist Version 2、保留的标准化三表、现有指标契约及验证回执。本轮不重算任何已验证经营指标，不修改口径或规则。

## 结论和状态解释

**足够支持历史交易金额异常定位及数量/均价分解，不足以支持“流量→广告→转化→库存→履约售后”的完整业务诊断。** 缺数据与实现未验证是两种问题，不能用下载另一个商家的数据修复 Olist 的证据缺口。

状态采用任务书五类：“已有数据，已验证”“已有数据，未验证”“部分支持”“完全缺失”“当前不需要”。“已验证”只在下列明确范围成立：历史七项核心指标及九组聚合已有独立验证；当前回放 76 个窗口通过原 SQL/JS 互核，但独立 Python 仅完成 17 个窗口、17,835 / 135,521 条商品分解。**未通过的剩余窗口不继承已验证标签。** 本轮只引用回执，详见 [存量盘点](EXISTING_DATA_INVENTORY.md)。

“当前不需要”是本轮任务范围判断，不代表该指标永远无价值。完全缺失仅指当前九表与三表，不表示世界上不存在数据。

## A．商品经营

| 指标 | 状态 | 已有证据与限制 | 是否需要新数据 |
| --- | --- | --- | --- |
| 原需求泛称的 GMV | 部分支持 | 已有两种商品金额；没有完整退款、退货、结算调整，不能称企业实际净 GMV | 若只做当前商品金额不需要；若要求净成交额必须补售后/财务定义与流水 |
| 历史已交付订单商品金额 | 已有数据，已验证 | v1 `amount_cents`；delivered 订单商品 price 合计，不含运费，七指标独立回执通过 | 不需要 |
| 购买订单商品金额 | 已有数据，已验证 | v2 既有状态集合和购买时间归属；限通过门禁及独立复核范围，不代表全部窗口已验证 | 不需要新来源；需另轮补齐未完成复核 |
| 按 product_id 的商品销售额/贡献 | 已有数据，已验证 | 商品金额及差额贡献；原引擎互核与 17 窗口独立证据可用 | 不需要 |
| 严格商家 SKU、规格、款式级销售额 | 部分支持 | product_id 是匿名产品标识，不是已经证明的商家 SKU/变体编码 | 要求该粒度时需卖家 SKU 映射及有效期 |
| 商品件数 | 已有数据，已验证 | 现有契约以商品明细行计件；不把 order_item_id 最大值当每商品数量 | 不需要 |
| 平均成交单价 | 已有数据，已验证 | 同范围商品金额÷件数；零件数不适用；不是挂牌价、折扣率 | 不需要 |
| 平均订单商品金额 | 已有数据，已验证 | 同范围商品金额÷去重订单数；与单件价格不同 | 不需要 |
| 商品数量效应、价格效应 | 已有数据，已验证 | 现有精确分数拆解；新增/消失商品用组合效应，没有双期价格效应；验证范围同上 | 不需要 |
| 品类贡献 | 部分支持 | 已实现且有复核；原商品品类缺失传导为 1,603 条 canonical 商品明细 category 为空，保留未知桶/门禁 | 不需另商家数据；要补全需 Olist 原品类映射 |
| 卖家/地区贡献 | 已有数据，已验证 | seller_id、customer_state 可用；按维度分组的订单数不一定可加总 | 不需要 |

## B．消费者流量

| 指标 | 状态 | 缺少什么 | 所需来源/边界 |
| --- | --- | --- | --- |
| 自然搜索流量 | 完全缺失 | 搜索来源、落地事件、用户/会话、商品键 | 同一商家站点分析/搜索平台；不能拿 B2B origin 替代 |
| 付费搜索流量 | 完全缺失 | 广告点击 ID、来源/媒介、会话及归因 | 同一商家广告与站点日志 |
| 广告曝光 | 完全缺失 | campaign/ad/product、曝光时间及数量 | 广告平台日志/报表 |
| 商品列表曝光 | 完全缺失 | list/view 事件及商品、位置 | 站内埋点；不等于广告曝光 |
| 点击 | 完全缺失 | 广告点击和商品点击的各自事件 | 分开定义，不能以订单数充当点击数 |
| CTR | 完全缺失 | 同范围同粒度的点击分子与曝光分母 | 必须先拥有两者，平均各行 CTR 不能代替汇总比率 |
| 商品详情页浏览 | 完全缺失 | view_item/页面事件及商品键 | 同一商家站点日志；订单评论不能反推浏览 |

## C．营销

| 指标 | 状态 | 缺少什么 | 所需来源/边界 |
| --- | --- | --- | --- |
| 广告花费 | 完全缺失 | 实际费用、币种、日期、账户/活动键 | 同一业务广告账单/平台导出 |
| 广告转化量/价值 | 完全缺失 | 点击/曝光→订单关联、去重转化 ID、归因窗/模型 | 订单总量不是广告转化量 |
| ROAS | 完全缺失 | 同范围真实费用与归因收入，币种及退款处理 | `归因收入 / 广告费用`；脱敏变换 cost 或 cpo 不能当原币金额 |
| 活动开始/结束时间 | 完全缺失 | 活动日历、目标商品、渠道、时区 | 不能因金额波峰推断正在促销 |
| 优惠、券、折扣率 | 完全缺失 | 原价、实售价、券/折扣分摊与活动关系 | price 是成交金额信息，不足以反推优惠力度 |

## D．转化

| 指标 | 状态 | 已有证据与缺口 | 所需来源 |
| --- | --- | --- | --- |
| 加购量/加购率 | 完全缺失 | 没有购物车事件或浏览分母 | 站点/APP 事件 |
| 下单量 | 已有数据，已验证 | orders 及既有购买订单量口径可用；全部订单与纳入经营状态订单不能混用 | 不需要 |
| 下单转化率 | 完全缺失 | 有订单，但无同 cohort 的用户/会话/访问分母 | 同一业务流量事件 |
| 支付方式、分期、订单支付记录金额 | 已有数据，未验证 | raw payments 已有，未进入当前三表；尚无独立支付对账指标验收 | 先审计现有表，不需先下载新数据 |
| 支付成功时点、支付尝试/失败及支付转化率 | 部分支持 | 有 payment_value/payment_type 和批准时间，但无支付尝试账本、支付状态及逐笔事件时间；批准时间不能直接当支付成功时间 | 同一业务支付网关/订单状态事件 |
| 全消费者漏斗转化率 | 完全缺失 | 缺前序访问/加购、身份衔接与支付事件 | 同源事件链；跨商家不可拼接 |

## E．库存

| 指标 | 状态 | 缺少什么 | 所需来源/边界 |
| --- | --- | --- | --- |
| 实存/可用/预占库存 | 完全缺失 | SKU×仓库×时点的数量及状态 | 同一商家的 WMS/ERP 快照 |
| 库存变化 | 完全缺失 | 连续快照、出入库/调拨/盘点流水 | 无销售不等于库存没变化 |
| 缺货及缺货时长 | 完全缺失 | 可售库存、营业/上架时段、快照覆盖 | 订单 unavailable 不能证明某 SKU 在某日缺货 |
| 补货量/到货/在途 | 完全缺失 | 采购/补货单、预计/实际到货及仓库键 | 库存差额不等于补货量 |

## F．履约和售后

| 指标 | 状态 | 已有证据与缺口 | 是否新增 |
| --- | --- | --- | --- |
| 订单最终状态分布/取消量 | 已有数据，已验证 | v1 状态聚合；历史最终快照，不是状态变更日志 | 现有分布不需新增 |
| 取消原因、取消时间、部分取消 | 部分支持 | 有 canceled 状态，无原因/时间/逐商品取消事件 | 要解释原因或历史时点需新增 |
| 发货时间/发货时长 | 已有数据，未验证 | raw `order_delivered_carrier_date` 可用，有缺失/顺序异常；当前 canonical 未保留该字段 | 先利用现有 raw，不需另商家数据 |
| 延迟订单量/延迟率 | 已有数据，已验证 | 仅合法实际和预计交付日期的 delivered 订单进入分母；已有 v1 复核 | 描述性指标不需新增 |
| 历史时点成熟履约告警 | 部分支持 | 最终日期存在不等于当时 cohort 已成熟；当前成熟证据不足时抑制 | 需 as-of 状态/履约事件与完整性声明 |
| 退款金额、退款率、退款原因 | 完全缺失 | 独立退款流水、币种、订单/商品关联及状态 | payment_value 不是退款记录 |
| 退货数量、退货率、原因 | 完全缺失 | 退货申请/实收/验收记录及逐商品键 | 取消或低评分不能代替退货 |
| 评分、低评分数/率 | 已有数据，已验证 | 原始评价多对一；现有契约每单选定一条评价，按 eligible 分母算 | 不需要 |
| 评论文本内容 | 已有数据，未验证 | raw 有标题/正文，但大量空值；三表未承载文本；未做文本分析验收 | 不需外部评论；另轮先评估现有文本 |
| 具体商品的评论归属/售后根因 | 部分支持 | 评论是订单级，多商品、多卖家订单不可无条件分配 | 若要确定归属需评论商品键或人工证据 |

## 当前不需要、不要扩大本轮范围

实时调度、跨商家 GMV 汇总、广告因果增量、自动预测缺货、LLM/NLP 建模：**当前不需要**。这些不是通过新增公开 CSV 就自动获得的能力。真实缺失项仍保留缺失；不得补零或把模拟值写入正式案例。

## 用于审核的最小补充数据契约（设计，未实施）

- 流量事件：business_id、event_id、event_time/timezone、event_name、user/session 标识、product/SKU、订单键、来源/媒介和 campaign/click_id；保存同意状态、采样/漏数说明。
- 广告日表：business/account/campaign/ad/product、report_date/timezone、impressions、clicks、spend、currency、conversion_count/value、归因窗口和导出修订时间；campaign→SKU 映射需显式有效期。
- 库存：business/SKU/warehouse、snapshot_at、on_hand/available/reserved；补货另有 movement_id、movement_type、quantity、事件时间。
- 售后/支付：business/order/order_item、payment/refund/return_id、时间、金额/数量、币种、状态、原因；支持多笔、部分退款和修订。

这些是建议采集的字段，不是已获取的真实值。来源、授权、键覆盖和时间一致性通过后，才讨论新增模块；详见 [关联可行性](DATA_JOIN_FEASIBILITY.md) 和 [获取优先级](DATA_ACQUISITION_PRIORITY.md)。
