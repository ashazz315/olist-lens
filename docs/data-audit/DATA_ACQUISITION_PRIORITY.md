# 数据获取优先级与人工审核方案

日期：2026-11-14。**本轮仅新增五份审计文档；不下载外部数据、不改业务代码、不重算指标、不运行集成、不推送或部署。** 所有下载和集成均留待人工审核。

## 八个决策问题

| 问题 | 审计结论 |
| --- | --- |
| 1．现有数据够不够支撑原需求？ | 足够支撑历史商品金额异常定位、数量/均价/组合分解及履约评价描述；不够支撑消费者流量、投放效率、库存和退款归因。这里按本轮列出的 A–F 需求审计，不臆造未提供的其他图中字段 |
| 2．哪些指标完全不需要新增来源？ | 当前两种商品金额、product_id 金额/件数/均价、订单量/客单商品金额、商品/品类/卖家/州贡献、最终订单状态、延迟和评分。评论文本、发货日期、支付方式/记录金额也已在 raw，先评估现有字段即可；这些新增分析能力尚不等于已验收 |
| 3．哪些必须新增？ | 同一业务的消费者流量/曝光/点击/加购、广告费用/归因、活动/优惠、SKU 库存/补货、退款退货；严格 SKU 映射、历史 as-of 状态和支付尝试事件也需按目标补充。净 GMV 必须先定财务口径并补相应调整流水 |
| 4．哪些最值得获取？ | 若优先独立消费者漏斗案例：GA4 混淆样本；若优先保留 Olist 关联：Marketing Funnel V2（仅 B2B）。库存研究可条件选择 Mendeley，先核实字典与真实性；广告研究 Criteo 可作受限备选。没有一个外部样本可直接补齐 Olist 全链路 |
| 5．哪些能关联？ | 仅 Marketing Funnel 具有发布方声明的 seller_id 关联路径，仍须实测验证；GA4、Mendeley 零售、Criteo、iPinYou 均必须作为独立业务源 |
| 6．获取后会增加什么真实能力？ | 见下表；能力只在各自数据业务范围内成立，并以质量/口径验收为前提，不能承诺经营改善或自动确认原因 |
| 7．需要修改哪些文件？ | 本轮 **没有已有文件需要修改**。仅新增本目录五份 Markdown；未来若获批，再新增独立来源适配/契约/测试，具体实施文件清单另行审查 |
| 8．哪些已完成模块完全不需修改？ | core.js、analysis.sql、operations.js、operations.sql、monitoring.js、monitor-store.js、worker.js、既有 UI、导入/恢复/导出与测试、正式快照/案例/PDF。缺广告或库存不构成修改旧口径/默认阈值的理由 |

## 分目标的优先级

| 优先级/目标 | 建议行动（未执行） | 真实可增加的能力 | 前置条件与边界 |
| --- | --- | --- | --- |
| P0：继续 Olist 商品诊断 | 复用现有九表/三表；单独处理上一轮运行故障与剩余复核 | 稳固已有金额/贡献证据；不需要下载同类交易数据 | 本轮不修复环境、不将未完成独立复核升级为通过 |
| P1：Olist 真正全链路 | 向同一业务的数据所有者申请授权站点、广告、库存、支付售后和映射 | 该业务真实漏斗、库存约束、退款后金额、可审查广告归因 | 当前未获得这些来源；没有权限/共同键时不能实施 |
| P1a：独立消费者漏斗展示 | 获取 GA4 公共样本的有限日期/字段 | Google Merchandise Store 的浏览—加购—购买方法案例 | 单独来源；混淆/一致性限制；先确认数据条款、schema 和查询预算 |
| P1b：Olist 卖家获客扩展 | 固定获取 Olist Marketing Funnel V2 | 卖家线索来源、入驻耗时与后续经营 cohort | 不是消费者流量；先核验 seller_id 覆盖、多线索及时间关系 |
| P2：独立库存研究 | 先核实 Mendeley 字典，再决定两 CSV 下载 | 若字段成立，独立门店×SKU 销售与库存时点描述 | 发布方业务来源待核实，行数/日期未知；不能宣称补货/缺货损失已可算 |
| P2：广告归因方法研究 | Criteo 单独样本，先保留费用变换和相对时间说明 | 曝光/点击/去重转化与归因窗检查 | 非原币成本，无商品销售收入，不能报告真实 ROAS |
| P3：其他广告日志 | iPinYou 仅在下载可达、单位/许可确认后考虑 | 竞价/曝光/点击/转化日志关联方法 | 年代久、日志体积/季次差异、价格缩放，无 Olist 键 |

P1a 与 P1b 是不同目标的选择，不建议为了“看起来完整”同时下载所有数据。广告检索未找到全面满足原币费用、自然日和收入要求的已核验公开源；不使用模拟营销 CSV 顶替。来源证据见 [外部审计](EXTERNAL_DATA_SOURCE_AUDIT.md)。

## 获批后的最小采集与验收计划

1. 审核人选择目标、数据源、允许用途/许可、版本、范围和查询/存储预算；确认只能独立使用还是可条件关联。**本轮到此等待审核。**
2. 在独立来源目录获取原归档/表导出；保存下载时间、公开元信息、版本、许可、文件名/大小、SHA-256、CRC（若归档提供）。不得覆盖 Olist 原文件或混入合成样本。
3. 核验实际行数/字段、主外键/冲突/空值、时间覆盖、事件或快照粒度、币种和单位。发布方声称的实体数量、日期不能代替实际计数。保留失败记录，不为通过而删改记录。
4. 按 [关联规则](DATA_JOIN_FEASIBILITY.md) 核验匹配和基数；没有共同业务键则中止业务合并。批准前不生成统一经营告警。
5. 仅为已获批的新能力写独立指标契约：事件/商品/卖家粒度、分母、窗口、排除项、成熟度和证据。原指标不变；新增来源不自动继承 Olist 默认阈值适用性。
6. 使用真实来源独立复核新结果；合成边界测试单独隔离。缺历史真值时不声称异常准确率、误报率、因果归因或业务改善。
