# Olist Lens v2.1 页面审查

经营驾驶舱用于判断两期经营变化、查看异常波及多少商品，并进入下一步调查。告警依据、商品明细和处理记录由各自页面承载。

## 业务前台

| 原入口 | 实用性判断 | 调整 |
| --- | --- | --- |
| 经营驾驶舱 | 能解释金额变化，但原来还承载大量商品明细、问答和模拟数据，影响扫读 | 保留两期金额对比、订单与销量等指标、异常范围和两个调查入口 |
| 监控与告警 | 需要独立查看触发条件；原入口容易与驾驶舱重复 | 集中展示告警、门槛与证据、正负向商品及分组贡献 |
| 商品 / SKU 分析 | 商品搜索或选择、量价分解和关联订单服务同一任务 | 保留商品入口，先选择商品，再显示这件商品的明细 |
| 营销、流量、转化、库存、履约 | 五项用于同一次调查；多数维度没有可以关联的真实 Olist 数据 | 归入「经营因素」并用子页切换。真实覆盖、独立来源与模拟样例分别标识 |
| 独立模拟与效果复核 | 适合演练调查和复核，容易与真实首页结果混淆 | 归入「经营因素」下的「模拟回放」，保留版本与时间窗口 |
| 调查助手 | 需要在看数据时随手追问，也需要完整浏览对话 | 保留右下角浮窗和独立调查页，共用同一会话 |
| 调查任务 | 支持审核、人工措施、记录执行和复核 | 保留权限门禁，任务状态以业务中文展示 |
| 报告中心 | 按当前版本导出，各格式用途不同 | 格式卡片说明用途，历史任务照旧从任务详情导出指定版本 |

## 管理后台

| 原入口 | 实用性判断 | 调整 |
| --- | --- | --- |
| 数据源 | 先了解是否已接入及适用范围，才需要底层配置 | 来源卡片先显示状态，配置可展开 |
| 导入、发布、回放调度 | 都属于数据接入流程；导入发布需要人工确认，调度才有自动执行 | 导入与发布在同一页，回放调度单列，放在同一导航组 |
| 版本、质量、指标规则 | 三处均用于核对版本是否适用和计算依据 | 合入「版本与质量」，通过子页保留三个用途 |
| 模型、权限、日志 | 访问控制、模型配置和审计职责不同 | 归入「系统设置」，保留三个独立页面 |

前后台使用一致的导航、数据工作区、状态标记、表格和表单。移动端通过菜单访问完整导航。历史快照和模拟样例沿用已有验证数据，告警规则、数据口径及角色权限仍由原流程执行。
